# Manuelle Rechnungssicherung am 07.11.2026

Im Bereich **Rechnungen** der Shop-Administration startet der Button **Rechnungen synchronisieren** den Abgleich. Öffne die Verwaltung auf dem Mac in Chrome oder Edge über die Hauptdomain und wähle nach dem Klick den vorhandenen Ordner **Buchhaltung**. Die Ansicht zeigt anschließend **Neu**, **Bereits vorhanden** und **Fehlgeschlagen**. [Shop-Administration](https://www.ultimatehikingleague.com/admin/shop)

Die bei Vercel gehostete Verwaltung hat keinen direkten Zugriff auf den Mac oder dessen LaunchAgent. Der Browser greift über seine native Ordnerauswahl auf den freigegebenen Ordner zu. Er prüft und schreibt die Dateien lokal im bisherigen Schema `Jahr/Ausgangsrechnungen/UHL-….pdf` mit passender `.sha256`-Datei. Ein lokaler Server oder eine Browsererweiterung ist dafür nicht erforderlich. [Chrome File System Access](https://developer.chrome.com/docs/capabilities/web-apis/file-system-access)

Der geschützte Server-Endpunkt prüft für jede Anfrage die Supabase-Sitzung und die Mitgliedschaft in `admin_users`. Er liefert seitenweise LIVE-Rechnungsnummern und bei Bedarf ein einzelnes bereits gespeichertes PDF mit SHA-256. Die Antworten sind privat und vom Cache ausgeschlossen. Die lokale Prüfung sendet weder PDFs noch Ordnerinhalte zum Server. Vorhandene Dateien werden mit ihrer erwarteten Kennung, PDF-Signatur und gespeicherten Prüfsumme verglichen. Eine fehlende oder abweichende Prüfsumme wird als Fehler angezeigt. Ein PDF-Download erfolgt ausschließlich bei fehlender PDF-Datei. Stimmen eine vorhandene Prüfsumme und der Serverinhalt in diesem Fall nicht überein, bleibt der Konflikt zur Prüfung sichtbar. Bei Fehlern in der Rechnungsauflistung zeigt die Oberfläche den bisherigen Zwischenstand.

Der Button blockiert Doppelklicks. Web Locks sperren weitere Tabs derselben Hauptdomain im gleichen Browserprofil während eines Laufs. Für denselben Sicherungsordner wird ein Browserprofil verwendet. Getrennte Profile und Geräte teilen diese Sperre nicht. Vor dem Schreiben prüft der Browser erneut auf eine vorhandene Datei und verwendet einen exklusiven Schreibstream. Eine eventuell bei einem Abbruch übrig gebliebene leere Datei wird beim Folgelauf als Fehler gemeldet. Den Fund vor einer manuellen Bereinigung prüfen. [Web Locks](https://developer.mozilla.org/en-US/docs/Web/API/Web_Locks_API)

Der bisherige LaunchAgent `de.ultimate.shop-invoice-backup` hatte `RunAtLoad` und ein Intervall von 300 Sekunden. Der Agent war beim Abschalten inaktiv zwischen zwei Läufen. Er ist aus dem GUI-Dienstbereich entladen und für spätere Anmeldungen deaktiviert. Die Plist, der letzte Status, Protokolle, PDFs und Prüfsummen bleiben als Bestand erhalten. Die Benutzer-Crontab war leer. Der bisherige Skripteinstieg verweist nun auf die Shop-Administration und endet vor einem Datenbankzugriff. Damit entfällt auch sein wöchentlicher Vollabgleich. Der produktive Vercel-Cron `/api/shop/jobs` führt weiterhin die Bestellverarbeitung aus. Die separate Statusjob-Route ist unveröffentlicht.
